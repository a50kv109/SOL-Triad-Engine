# Архитектурное предложение: AAM Language Kernel как Semantic Gateway для SOL-Triad

**Проект:** SOL-Triad-Engine / AAM-Language-Kernels  
**Документ:** Архитектурное исследование семантического шлюза  
**Статус:** PROPOSAL / RESEARCH  
**Дата:** 2026-10-30  

---

## 1. Архитектурная схема

Предлагаемая сквозная архитектура разделяет процесс обработки запроса на лингвистический шлюз, семантическую нормализацию и детерминированную инженерную проверку:

```
[ Natural Language Input ] (RU, UK, EN, etc.)
            │
            ▼
┌───────────────────────────────────────┐
│         AAM Language Kernel           │  ← Распознавание языка, извлечение намерений,
│   (Language ID & Intent Extraction)   │     обнаружение неоднозначностей и неопределённостей
└───────────────────────────────────────┘
            │
            ▼
┌───────────────────────────────────────┐
│    Sanskrit Dhatu Semantic Layer      │  ← Канонический словарь инвариантных операций (32 Dhatu)
│   (Semantic Operations & Operators)   │     и лингвистических ролей (Karaka)
└───────────────────────────────────────┘
            │
            ▼
┌───────────────────────────────────────┐
│     Canonical Semantic Intent (CSI)   │  ← Формализованный контракт намерений, параметров,
│    (Structured Neutral Contract)      │     неопределённостей и происхождения (execution_authorized: false)
└───────────────────────────────────────┘
            │
            ▼
┌───────────────────────────────────────┐
│       SOL-Triad JSON Adapter          │  ← Строгая валидация структуры протокола v0.4.0
└───────────────────────────────────────┘
            │
            ▼
┌───────────────────────────────────────┐
│      SOL-Triad Engineering Core       │  ← Детерминированная проверка инвариантов (SOURCE, CONSTRAINT, DISSIPATE)
│     (v0.4.1 Deterministic Engine)     │     Verdict: PASS / REVIEW / FAIL
└───────────────────────────────────────┘
```

## 2. Распределение ответственности модулей

Для обеспечения чистоты архитектуры и независимости аудита устанавливаются строгие границы ответственности:

| Модуль | Зона ответственности | Что модуль **НЕ** делает |
| :--- | :--- | :--- |
| **AAM Language Kernel** | Распознавание естественного языка (русский, английский, украинский и др.), извлечение сущностей, фиксация синтаксиса, обнаружение неоднозначностей. | Не производит инженерных расчетов, не принимает решений о допустимости состояний. |
| **Sanskrit Dhatu Semantic Layer** | Предоставление стабильного словаря из 32 канонических корневых операций (`√man`, `√tula`, `√hri`, `√tapa` и др.) и системы ролей (`Karaka`). | Не является филологическим абсолютом; используется как проектная онтология вычислительных операций. |
| **Canonical Semantic Intent (CSI)** | Промежуточный формализованный контракт, описывающий структуру запроса, параметры, единицы измерения, пропущенные данные и флаг авторизации (`execution_authorized: false`). | Не является исполняемой командой сама по себе; требует явного разрешения и валидации. |
| **SOL-Triad Engine** | Строгая детерминированная проверка инженерных инвариантов по примитивам `SOURCE`, `CONSTRAINT`, `DISSIPATE` и выдача вердикта (`PASS`, `REVIEW`, `FAIL`). | Не занимается парсингом естественного языка или разрешением лексических синонимов. |

## 3. Предлагаемый контракт Canonical Semantic Intent (CSI)

Ниже приведена структура JSON-контракта, связывающего семантический шлюз с детерминированным ядром:

```json
{
  "intent_id": "intent-20261030-001",
  "source_language": "ru",
  "original_text": "Система перегревается, необходимо ограничить температуру до 85 C и рассеять избыточное тепло через контур охлаждения.",
  "normalized_intent": "limit_temperature_and_dissipate_heat",
  "actors": [
    {
      "role": "agent",
      "entity": "cooling_controller"
    }
  ],
  "actions": [
    {
      "dhatu_root": "√tapa",
      "operation": "HEAT_FLOW",
      "sol_role": "SOURCE"
    },
    {
      "dhatu_root": "√hri",
      "operation": "LIMIT",
      "sol_role": "CONSTRAINT"
    },
    {
      "dhatu_root": "√kamp",
      "operation": "DAMP",
      "sol_role": "DISSIPATE"
    }
  ],
  "objects": [
    "engine_core",
    "cooling_loop"
  ],
  "parameters": {
    "temperature": 85.0
  },
  "units": {
    "temperature": "c"
  },
  "constraints": {
    "max_bounds": {
      "temperature": 85.0
    }
  },
  "temporal_relations": {
    "evaluation_time": 1740000000.0
  },
  "dhatu_mapping": [
    { "token": "нагрев", "dhatu": "√tapa" },
    { "token": "ограничить", "dhatu": "√hri" },
    { "token": "рассеять", "dhatu": "√kamp" }
  ],
  "ambiguity": [],
  "missing_information": [],
  "provenance": {
    "source_text": "Система перегревается...",
    "language_kernel": "rus",
    "semantic_gateway": "AAM-V2",
    "axis_10_version": "0.4.1"
  },
  "confidence": 0.95,
  "execution_authorized": false
}
```

*Примечание:* Поле `confidence` отражает степень уверенности парсера, но не является доказательством корректности. При наличии пропущенных данных поле `missing_information` заполняется списком необходимых параметров, а `execution_authorized` остается `false`.

## 4. Пример преобразования естественного языка в CSI

**Входная фраза (RU):**  
> *"Внимание, давление в топливном баке падает ниже 2.5 бар, требуется аварийный подпор."*

**Этапы обработки:**
1. **AAM Language Kernel:** Определен русский язык (`ru`), выделен объект (`fuel_tank_pressure`), параметр (`2.5`), единица (`бар`), намерение (обнаружение падения давления и запрос подпора).
2. **Sanskrit Dhatu Layer:** Применены корни `√man` (MEASURE / SOURCE), `√tula` (COMPARE / CONSTRAINT), `√shas` (CONTROL).
3. **Формирование CSI:**
   - `parameter`: `pressure = 2.5`
   - `units`: `{ "pressure": "bar" }`
   - `min_bounds`: `{ "pressure": 2.5 }`
   - `missing_information`: []
   - `execution_authorized`: `false`

## 5. Риски и ограничения

1. **Семантический дрейф (Semantic Drift):** Различные формулировки одной и той же физической ситуации могут интерпретироваться по-разному. Требуется жесткая калибровка словаря Dhatu.
2. **Иллюзорная уверенность (Hallucination of Parameters):** Языковая модель может попытаться самостоятельно подставить критические инженерные константы, если они не указаны пользователем. CSI должен строго пресекать это, возвращая статус `NEEDS_CLARIFICATION`.
3. **Лингво-философская условность:** Сопоставление санскритских корней с инженерными операциями является разработкой проекта, а не историческим фактом. Терминология должна трактоваться исключительно как канонический внутренний словарь.

## 6. План создания независимого прототипа (Sanskrit Dhatu Semantic Adapter v0.1)

Для проверки гипотезы без вмешательства в рабочее ядро SOL-Triad предлагается создать автономный тестовый пакет:
- **Расположение:** `prototypes/dhatu_adapter_v0.1/`
- **Тестовый банк:** 30 инженерных фраз (по 10 на английском, русском и украинском языках), охватывающих:
  - Отрицания и запреты («Не допускать превышения...»)
  - Числовые границы и единицы («Температура не выше 300 К»)
  - Неполные данные («Ограничить давление...» без указания значения)
  - Противоречивые требования
- **Критерии успешности прототипа:**
  1. Эквивалентные запросы на RU, EN и UK приводят к идентичной структуре `dhatu_mapping` и `constraints`.
  2. Пропущенные параметры корректно фиксируются в `missing_information`.
  3. Флаг `execution_authorized` во всех неполных запросах равен `false`.

## 7. Критерии успешного тестирования шлюза

- Отсутствие несанкционированной подстановки физических величин.
- Стопроцентное сохранение знака отрицания в логических условиях.
- Корректная трансляция единиц измерения (`бар`, `кПа`, `К`, `°C`, `с`) в формат, поддерживаемый `UnitRegistry`.

---

## 8. Условия будущей интеграции с SOL-Triad

Интеграция семантического шлюза с SOL-Triad возможна только после:
1. Завершения и успешного прохождения всех тестов прототипа `v0.1`.
2. Подтверждения того, что шлюз не генерирует ложных срабатываний и корректно передает управление на уточнение при неоднозначности.
3. Сохранения полной изоляции: шлюз подготавливает JSON-запрос, соответствующий схеме `SolTriadJsonAdapter`, а детерминированное ядро производит расчет без учета того, был ли запрос введен вручную или сгенерирован языковым шлюзом.

## 9. Экспертный ответ на ключевой вопрос

> **Вопрос:** Может ли такое языковое ядро повысить определённость входных данных SOL-Triad, не нарушая детерминизм самого SOL-Triad?

**Ответ:**  
**Да, может.** 
Языковое ядро и семантический слой Dhatu выступают в роли **нормализатора входных данных**, устраняя неоднозначность естественного языка и приводя запросы к единому структурированному контракту (CSI). При этом детерминизм SOL-Triad **не нарушается** по следующим причинам:
1. SOL-Triad по-прежнему получает на вход строго типизированный детерминированный JSON, свободный от лингвистической неопределенности.
2. Если языковой шлюз обнаруживает неполноту или двусмысленность параметров, он не передает некорректные данные в движок, а останавливает выполнение (`execution_authorized: false` или запрос уточнения).
3. Вычислительное ядро остается чистой математической функцией проверки инвариантов, полностью изолированной от вариативности человеческого языка.
